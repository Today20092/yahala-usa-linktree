# 0.2.0 release candidate

This development batch adds the `/contact` partnership flow, refreshes the home,
About and Stories pages, and updates story discovery, maps, shared navigation,
motion, branding and page share images. Shared primitives use Base UI.

Existing public routes remain available. The partnership inbox and Turnstile
site key remain intentionally blank: visitors can prepare and copy an inquiry,
but the website does not deliver email. Analytics is also disabled until a token
is configured. No stored-data migration or version tag is part of this release.

## Verification

The release candidate includes the November 5 remote catalog update at
`0eb5e54`. Validation ran on Windows with Node 26.3.0; GitHub CI uses Node 22.

- `npm ci` passed.
- All CI source checks, data/UI validation and regression scripts passed.
- Both partnership TSX regression scripts passed through `npx --yes tsx`.
- `npm run build` and `npm run smoke:preview -- dist` passed.
- `npm run test:a11y:full` passed all 30 browser tests across six viewport/theme
  combinations, including contact keyboard/validation/recovery checks.
- Corrected CI to run the full accessibility matrix required by the existing
  dependency merge guard. Corrected the smoke fixture/assertion for the native
  QR dialog; a missing-dialog regression still fails as expected.

Manual screen-reader testing, actual browser zoom, physical devices and a full
accessibility assessment were not repeated. Axe incomplete findings remain in
local ignored reports. Local research artifacts under `artifacts/` are excluded.

## Known limits and recovery

`npm audit` reports 17 vulnerabilities, including the existing critical
MapLibre sanitizer advisory GHSA-jrc7-96c5-q579. Its suggested fix upgrades
MapLibre from 5.x to 6.16.0; that migration is outside this release batch.
The build also reports the missing optional local icon directory and large
chunks. Astro check reports two unused-code hints, with no errors or warnings.

Source can be rolled back by reverting the promotion merge and redeploying.
Production deployment status is established by the GitHub Deploy workflow,
separately from this local verification record.
